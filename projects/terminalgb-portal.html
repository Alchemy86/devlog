What it is

A companion web service for TerminalGB that lets two people trade a Gen 1 Pokémon without either of them owning a second Game Boy. A link trade only ever needed one real console and a partner on the other end of the cable that answers correctly — and the emulator already ships that partner (its gen1-link virtual partner, fed by a PokemonSource). The portal is simply a PokemonSource served over HTTPS, so a trade becomes a handful of ordinary HTTP requests.

Because of that, nothing is synchronised and nobody waits: each player trades against their own local partner, in their own time. What actually crosses the wire is a roughly 250-byte description of a Pokémon — species, level, original trainer, moves, DVs — and never game bytes, never a save, never a ROM. That is a deliberate licence boundary, not an implementation shortcut.

The trade loop

v1 is a small, closed set of features, each one doing exactly one thing:

  • Device-code login — terminalgb login runs the RFC 8628 device-code flow; the portal serves the endpoints the command calls and the approval page.
  • Friends by code — you get a six-character code and paste a friend's; the codes are rate-limited and non-enumerable.
  • Offer and accept — you offer one Pokémon to accepted friends; the first to accept locks it atomically, naming what they give back. The confirm screen states exactly what leaves and what arrives, because a trade is irreversible.
  • Trade log — both parties see the same rows.
  • Collection browser — a friend's party and boxes, browsable and filterable, with sprites held for the session only: they vanish when the terminal disconnects and the portal keeps no sprite store of its own.

Stack: Next.js 15, Clerk for auth, Postgres, plain pg with no ORM, deployed to Vercel — $0/month at hobby scale. The HTTP API is a shared contract with the emulator repo.

Milestones

15 Aug 2026

Draw the card the emulator sends

The portal reads the ~250-byte Pokémon description the terminal reports and renders it as a card — one shared card shape used everywhere offers appear.

14 Aug 2026

Collection browser with session-only sprites

Live party-and-box listings of what a friend's own terminal reported, filterable by species, type, level and storage — including the "would be shiny if traded to Gen 2" prediction that Gen 1 itself cannot show.

14 Aug 2026

v1: the whole trade loop

Sign in, add a friend by code, offer and accept a single Gen 1 Pokémon with an atomic lock, and a shared trade log — the complete first version, backed by 65 end-to-end checks against a running server.

Deliberately not in v1

The UI says so where it matters: live link sessions and battles, the browser as a primary client, strangers and public matchmaking, multi-Pokémon trades, Gen 2/3, and mobile are all out of scope for the first version. The emulator-side sender that pushes a collection to the portal is not built yet — the contract for it is written down and waiting.

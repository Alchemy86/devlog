What it is

TerminalGB emulates the original DMG and the Color hardware down to the machine cycle. It ships two picture engines: standard, which draws a scanline at a time and is fast enough for modest hardware, and identical, which walks the real pixel pipeline dot by dot and is exact enough to catch single-dot timing bugs. On ordinary games the two produce byte-identical frames; the only axis between them is exactness against speed.

Nothing on this page is asserted without a test behind it. The reference suites cited — Mooneye GB, SameSuite, Mealybug Tearoom, AGE, Gambatte — are public, and every comparison is re-run against hardware-photographed frames each build.

Milestones

24 Aug 2026

The double-speed pixel fix Write-up

A one-dot LCDC write-commit stagger, calibrated on single-speed ROMs, had no room to land once the CPU clock doubled — so it silently vanished and a Color game drew a wrong stripe. The AGE ROM m3-bg-lcdc-ds@cgbBCE went from 2,304 wrong pixels to a pixel-exact pass, with five more double-speed rows falling sharply. Read the full write-up →

21 Aug 2026

OAM DMA drives the right bus

OAM DMA now drives the address bus the picture processor reads sprite memory on, matching how real hardware behaves for sprites during a transfer — the source and the PPU are no longer allowed to disagree about what OAM holds.

20 Aug 2026

The accurate engine becomes the default

identical stopped losing accuracy rows that the fast engine was still passing, so it was promoted to the shipping default. The GB Emulator Shootout score moved 223 → 238 rows on the switch.

18 Aug 2026

$FEA0–$FEFF is not a hole

The "forbidden" region between OAM and I/O is modelled as unmasked RAM rather than dead space, which is what the two accuracy suites that actually reach it expect — closing a class of Color failures (cgb-acid-hell).
